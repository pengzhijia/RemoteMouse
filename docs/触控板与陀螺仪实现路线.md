# RemoteMouse：系统遥控器触控板与陀螺仪实现路线

记录日期：2026-11-09。本文是研发计划，不代表功能已经完成。

## 用户目标与约束

- 继续在现有 RemoteMouse 项目研发，优先保持 iPhone 控制中心自带 Apple TV 遥控器作为手机入口。
- 实现接近 Mac 触控板的移动、点击、拖动、双指滚动、缩放、旋转和三/四指手势。
- 探索混合输入：iPhone 姿态/陀螺仪控制鼠标移动，系统遥控器触控区域负责点击、拖动和手势。
- 沿用已有原生 Swift macOS 和 WPF Windows 控制台、按键映射、PIN 设置、配对与加密连接。
- 不把重建项目、增加配置入口或电脑端生成模拟坐标作为已解决手机多指采集的证据。若需要独立手机采集端，应先解释与保留系统遥控器入口的冲突，再让用户选择。

## 当前证据

- 当前使用 Companion Link。主要接收旧式 `_touchStart`、`_hidT`、`_hidC`。
- 单指鼠标移动和此前通过特殊报文识别的双指轻点右键，用户已实测成功。
- 之前单/双指滑动的受控测试，没有得到两条可可靠区分的连续坐标流；这只约束已测设备与系统，不能证明所有 Companion Link 版本均不支持多指。
- `_tFg` / 新版 `TouchFinger` 有表达手指标识的线索；字段含义、取值、并发触点和接收行为仍需实证。存在字段不等于已验证多指功能。
- 三指、四指映射和多触点解析是预留能力，尚未验证 iPhone 系统遥控器实际能触发。
- 没有从当前系统遥控器报文中验证出手机姿态、角速度或加速度数据。当前工程没有 iPhone 运动数据采集端。

## 实施顺序与通过标准

### 第一阶段：验证系统遥控器究竟发送什么

1. 保留稳定版，单独构建协议研究版，尽量维持应用身份，避免反复重置辅助功能权限干扰判断。
2. 记录触控会话请求/响应、完整解码事件、时间戳和实际报文名称。严格区分手机输入与控制台测试动作。
3. 核对 `_touchStart` 的尺寸、`_tFl` 和返回标识的真实语义；不猜测旗标、不盲目宣告多指能力。
4. 补充并验证新版 `HIDTouchStart` / `HIDTouch` / `HIDTouchStop` 路径。分别处理 `TouchFinger`、`TouchPhase`、`CoordinateX/Y`、`Nanoseconds`。
5. **不能直接混用新旧 phase 数值。** 逆向资料对新版 Ended/Cancelled 的描述与当前旧路径假设不同，需独立验证；取消不能触发点击或手势。
6. 受控采集：单指/双指/三指静止、平移、相向捏合、旋转、先后抬指、取消；分别标注手机型号、真实 iOS 版本和触摸/方向键布局。
7. 多指通过标准：在重叠时间段出现可区分的两个/三个触点，独立坐标随各自手指运动变化，连续重复测试成立。不能仅把 `_tFg=2` 当成证明，也不能用异常结束报文还原不存在的轨迹。
8. 若始终只有单触点，记录当前验证范围与限制。先继续检查协商与其他事件，再决定是否需要手机端采集程序。更换电脑端工程不能凭空补齐发送端数据。

### 第二阶段：实现可靠的触控板行为

- 先完善单指点击/双击/按住拖动及取消、断连、退出时的释放，防止鼠标按键卡住。
- 确认多触点后，建立按触点 ID 跟踪的状态机；以位移、时间和触点变化区分轻点、滚动、捏合、旋转和多指滑动，避免同时触发点击。
- 双指滚动：重心位移、细小位移累积、自然滚动、可调惯性。缩放：两点距离变化；旋转：两点夹角变化。
- 三/四指滑动：映射桌面切换、Mission Control 等；按系统快捷键配置执行功能。快捷键动作不等同于原生连续手势动画。
- Mac 的逐帧缩放、旋转和系统手势注入需要另行验证可用接口；公开鼠标/滚轮事件能执行基本操作，不保证能注册为完整 Magic Trackpad 或获得所有原生手势语义。虚拟多点 HID/驱动属于后续独立可行性评估。
- Windows 保留同一识别状态机，输出对应 Win32 输入和用户配置的快捷键。
- 轨迹视图仅画真实收到的触点；显示实测最大并发触点数、事件路径和取消原因，标记“已验证/未验证”。

### 第三阶段：姿态控制鼠标，触控区负责手势

技术上可做“空中鼠标”，但必须先取得手机运动数据。

1. **优先研究系统遥控器自身是否发送运动数据或提供可验证的订阅/协商方式。** 当前尚无证据，不能承诺仅升级 Mac/Windows 接收端即可取得陀螺仪。
2. 若系统遥控器不提供运动数据，评估额外手机采集端使用 Core Motion 的 `CMDeviceMotion`（attitude、rotationRate、gravity 等）。它可以走独立加密通道，与 Companion Link 触控通道在电脑端合并。
3. 额外采集端与控制中心系统遥控器并用时，必须实测切换前台、展开控制中心、息屏和锁屏后的持续采样。iOS 后台应用可能挂起，不能把后台陀螺仪持续采集当成既定能力；不以滥用音频或定位后台模式维持运行。
4. 如果无法与系统遥控器稳定并用，完整前台原生手机触控+运动采集界面是另一条路线，但会改变用户当前的入口约束，需另行决定。Safari 页面同样要验证权限、页面可见性和控制中心遮挡后的采样。
5. 使用融合后的姿态（四元数）或角速度计算鼠标位移；设置中立姿态、灵敏度、低通滤波、死区、漂移校正与重新居中。优先以相对转动控制光标，不对加速度双重积分来假装获取稳定的空间绝对位置。
6. 协议包含会话绑定、单调时间戳、序号、姿态/角速度；目标采样 60–120 Hz 需实测延迟、功耗与丢包，不能预先保证。
7. 提供启停/离合（clutch）动作：调整握姿时冻结鼠标，恢复时重新建立参考，防止光标跳变。
8. 合并输入规则：姿态只负责移动；触控用于左/右键、拖动、滚动与手势。触控开始/手势识别/拖动期间是否冻结姿态，应可配置并通过实际操作验证。
9. 姿态数据过期、断连、采样中断时立即停止位移并释放按键；重新连接必须重新校准。

## 下一次应先做什么

先完成“第一阶段”的新旧触控路径与实证测试；同时研究系统遥控器是否存在运动数据通道。取得真实多指/运动数据前，不承诺完整触控板或陀螺仪功能。当前没有修改稳定包去假装完成这些能力。
